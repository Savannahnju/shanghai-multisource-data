## 3. 被放弃 / 被修正的 AI 输出

| AI 输出 | 处置 | 原因 |
|---|---|---|
| 把 POI 大类→产业大类 的字典映射表述为"数据挖掘方法" | 放弃 | 属 Schema Matching / 语义映射，不满足课程对聚类、分类、关联规则的定义 |
| "生产性服务业即第二产业"的默认归类 | 修正 | 计数证明其中 96% 以上仍是服务业实体，工业仅 3,633 条；已单列检验 |
| GPKG WKB 手写解析 | 放弃 | 修复偏移量后仍存在区名与几何整体错配，改用 geojson |
| 多边形面积加权质心公式 | 修正 | 实现有误导致标注缺失/错位，改用属性表自带质心字段 |
| 随机抽 30 个乡镇做样本 | 放弃 | 无法代表空间形态，改为人工分层抽样（黄浦/青浦/崇明） |
| Kruskal-Wallis 直接用于含 n=1 簇的检验 | 修正 | 该簇无方差，p 值不可靠；补 Mann-Whitney U 并说明 |
| "PM2.5 与产业结构不存在关联"的表述 | 修正 | N=16 时 \|ρ\|=0.5 功效仅 52%，改为"不可检出" |

## 4. 核验方法小结

1. **数字类**：所有系数、p 值、计数必须来自脚本实跑输出，写入报告前抽查回溯到 `analysis/output/*.csv`；
2. **关键结论**：至少一处人工独立复算（最强的 ρ=0.689 / p=0.0031 用升序明细表复现）；
3. **代码类**：一律真实执行，报错即修，不采信未运行的代码；断言写进脚本（行数、键唯一、无缺失、占比行和）；
4. **表述类**：要求 AI 区分"事实 / 推断 / 不可检出"，涉及机理的解释保留讨论措辞。

## 5. 心得与反思

- **效率**：AI 把需求解析、脚本骨架、图表模板、README 框架的时间压缩到原来的三分之一左右；尤其 K-means 的稳定性检验（20 种子 ARI）与 choropleth 的手绘实现，若手写耗时明显更长。
- **提示词经验**：最有效的两句是"数字必须来自真实运行输出"和"先给可复现脚本，再给结论"。前者抑制编造统计值，后者把讨论拉回可验证层面。
- **失败教训**：AI 对数据真实结构会"想当然"——把中间表当 UTF-8、把 pandas 索引当对齐键、把 gpkg 几何当正确。这三次错误都只能靠实际运行与人工抽查暴露，不能靠读代码发现。
- **边界**：AI 适合做初稿、脚手架与排障；不适合替代统计判断。多重比较该用哪种校正、阴性结果如何表述、n=1 簇是否可检验，最终都由人决定，并在报告中留下判断依据。
- **对研究的影响**：AI 曾让我差点把"字典映射"当成数据挖掘方法、把"生产性服务业"当成第二产业；两次纠偏都来自"要求给出反证"的追问方式，这也是本项目中与 AI 协作最该保留的习惯。
