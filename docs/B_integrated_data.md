# B · 融合数据说明（Integrated Data）

> 研究问题（Q1）：**城市环境质量是否与地铁客流量（2017 年）有关？**
> 本文件说明 B 负责的多源数据如何关联并融合为一张「区 × 月」分析宽表。

---

## 1. 交付文件

| 文件 | 位置 | 说明 |
|---|---|---|
| `fused_environment_metro_2017.csv` | `output/` | 最终融合宽表，52 行 × 12 列 |
| `fuse_environment_metro.py` | `可复现脚本/` | 一键重跑融合脚本 |
| `fusion_log.txt` | `output/` | 数据量 / 剔除 / 校验日志 |

## 2. 融合输入（5 个数据源）

| # | 数据源 | 粒度 | 用途 |
|---|---|---|---|
| 1 | `metroData_InOutFlow.csv` | 站点 × 10 分钟 | 主数据，聚合到区 × 月 |
| 2 | `站点_区映射.csv` | 站点 → 区（302 站） | 空间聚合（站点归区） |
| 3 | `2017年各区降尘量与PM2.5月均浓度.xlsx` | 区 × 月 | 环境质量自变量 |
| 4 | `workday_calendar.csv` | 日 | 月级工作日数控制变量 |
| 5 | `shanghai_weatherHourly.csv` | 逐小时（全市单点） | 月级温/雨控制变量 |

## 3. 融合方式（三步）

1. **空间关联**：站点经纬度「点面相交」→ `站点_区映射.csv`，302 站归入 13 区（3 个昆山站剔除；奉贤/金山/崇明无站点，不补 0）。
2. **时间对齐**：客流与环境统一截取 2017-05 ~ 08；客流按 `date` 前 6 位取月份，环境按 xlsx 的 5–8 月列；工作日/气象聚合到月。
3. **主键合并**：三侧统一到 **`区名 + 月份`** 主键后 inner join，生成 13 区 × 4 月 = 52 个观测。

## 4. 融合宽表数据字典（12 字段）

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| 区名 | str | — | 16 区标准名（实际 13 个有站区） |
| 月份 | int | 5/6/7/8 | 2017 年 5–8 月 |
| 降尘量 | float | t/(km²·月) | 该区该月降尘量 |
| PM2.5 | float | μg/m³ | 该区该月 PM2.5 月均浓度 |
| 地铁总客流 | int | 人次 | 该区该月进出站客流之和 Σ(inFlow+outFlow) |
| 地铁日均客流 | float | 人次/日 | 总客流 ÷ 有效天数 |
| 客流强度 | float | 人次/站·月 | 总客流 ÷ 站点数（推荐主因变量） |
| 站点数 | int | 个 | 该区地铁站点数 |
| 有效天数 | int | 天 | 该区该月有效运营天数 |
| 工作日数 | int | 天 | 该月有效工作日数（全市一致） |
| 月均温 | float | ℃ | 该月日均气温月均值（全市一致） |
| 月总降雨 | float | mm | 该月日降雨量合计（全市一致） |

## 5. 校验结果

- 主键 `区名 + 月份` 唯一，**无重复、无缺失、无笛卡尔积**；
- 断言通过：**13 区、52 行、无重复区月、无缺失值**；
- 编码：**UTF-8 with BOM（utf-8-sig）**，Excel 双击打开不乱码。

## 6. 复现命令

```bash
cd Q1_融合分析/可复现脚本
python -I fuse_environment_metro.py
```

输出：`output/` 下 4 个 CSV（含 `fused_environment_metro_2017.csv`）+ `fusion_log.txt`。
