## 1. 通用清洗要求

| 维度 | 要求 | 具体口径 |
|---|---|---|
| 编码 | 输入按原编码读取，输出统一 UTF-8-SIG | 原始 POI 为 UTF-8（带 BOM），读取用 `utf-8`；若首列出现 `\ufeff` 改用 `utf-8-sig`。区界 geojson 为 UTF-8。所有 CSV 一律 `encoding='utf-8-sig'`、`index=False`，禁止中间表写成 GBK |
| 坐标系 | 全流程统一 WGS-84（EPSG:4326） | POI 使用 `经度_WGS84` / `纬度_WGS84`，不得混用 GCJ-02；区界同为 WGS-84。GCJ-02 与 WGS-84 之间存在约数百米系统性偏移，混接会导致边界点错区。面积计算投影至 WGS-84 UTM Zone 51N（EPSG:32651），不用地理坐标系下以“度”为单位的 `Shape_Area` |
| 单位 | 各字段单位随列名保留，不自创单位 | POI 计数为“条”；密度为“个/km²”；占比为“%”；浓度为“μg/m³”；AQI 优良率为“%”（0—100）；面积为“km²”；降尘量为“t/(km²·月)” |
| 去重 | 按业务唯一键去重，保留首条 | POI：`ID` 为全局唯一键；若 `ID` 仍有重复，辅以 `名称 + 经度_WGS84 + 纬度_WGS84 + 大类`。空气：`区名 + 年份 + 月份` 唯一。区界：`district` 唯一（16 行） |
| 缺失 | 不用 0 填充，处置须留档 | POI 的 `名称` / `大类` / `中类` / 经纬度缺失率须为 0；空气缺失按“线性插值 / 同区其他年月均值 / 删除”三选一，记录条数与处置方式 |
| 异常值 | 领域硬规则剔除，统计规则只标记 | 负浓度、AQI 越界、坐标越界等硬规则直接剔除；1.5×IQR 只新增 `is_outlier` 标记列，不删除，并记录规则、条数与示例 |
| 命名与输出 | 中文列名、中文产物名、统一写出参数 | 列名保留原始中文及单位（如 `PM2.5(μg/m³)`）；输出至 `cleaned_Data/`；文件命名见 §4.1 |

### 2.2 清洗动作（按执行顺序）

1. **删除无效列**：永久删除 `省份`、`城市`、`区县` 3 列。
2. **坐标范围校验**：仅保留 `120.8 ≤ 经度_WGS84 ≤ 122.0` 且 `30.6 ≤ 纬度_WGS84 ≤ 31.9` 的点，越界剔除。当前实现越界 **1 条**。
3. **异常大类过滤**：剔除 `虚拟数据`、`室内设施`、`事件活动`。源要求按 38 + 22 + 4 **预计剔除 64 条**、剩余约 **1,422,913 条**；现行清洗实际剔除 **59 条**。原要求存在两种口径，需与成员 E 确认。
4. **去重**：`drop_duplicates(subset=['ID'])`，保留首条；当前实现剔除重复 **82,138 条**（5.77%）。`ID` 若有重复，再以 `名称 + 坐标 + 大类` 去重。
5. **空间连接（核心步骤）**：以 WGS-84 点与区界多边形做 `geopandas.sjoin(how='left', predicate='within')`，为每个 POI 赋予 `所属区县`（现行落库列名 `区名`）。地址字段无法稳定解析区县（如 `层林路560号` 不含区名），空间连接是获取真实区县的唯一途径。源要求对边界未匹配点“人工核查或用最近区补全”；现行实现不插补，未落区 **1,251 条（0.09%）** 在分区统计中自然排除。原要求存在两种口径，需与成员 E 确认。
6. **产业映射**：按本节映射表生成 `产业大类`，确保每个 POI 均有归属、无 NaN。
7. **分母修正**：`居住地址标识`（地名地址信息）占各区 POI 总量的 **9.7%（黄浦区）至 29.0%（崇明区）**，非产业实体；若留在分母，会以不同比例稀释其余产业占比。故**剔除该类别，对剩余 12 类重新归一化**，作为产业结构主口径，每区 12 类占比合计应为 100（偏差 < 0.1）。
8. **保存**：清洗结果写 `cleaned_Data/`，`index=False`、`encoding='utf-8-sig'`。

### 2.3 区界底图清洗（空间连接前置）

原始区界提供三种同源格式：`区级数据.csv`（16 行 × 8 列，含 WKT）、`区级数据.shp`（含 `.dbf/.shx/.prj/.cpg/.sbn/.sbx/.xml`）、`区级数据.geojson`。

| 字段 | 类型 | 含义 |
|---|---|---|
| WKT | string | 多边形/多多边形边界文本（WGS84） |
| Id | int | 要素编号 |
| city | string | 城市名（全为“上海市”） |
| district | string | 区县名称（16 区，关联关键字段） |
| citycode | int | 城市编码 |
| adcode | int | 行政区划代码 |
| Shape_Leng | float | 边界周长 |
| Shape_Area | float | 边界面积（度单位，非真实 km²） |

清洗动作：

1. **WKT 解析**：`wkt.loads` 后转 `GeoDataFrame(crs='EPSG:4326')`；核验要素数为 **16**、几何类型为 `Polygon/MultiPolygon`、无无效/空几何。
2. **面积重算**：投影至 `EPSG:32651`（WGS84 UTM Zone 51N），`area_km2 = geometry.area / 1e6`（m² → km²）。
3. **区名标准化**：与空气、POI 三源逐字对齐，统一为 16 个标准名（见 §3.2），`str.strip()` 去空格，别名映射修正。
4. **保存**：GeoPackage `district_boundaries_clean.gpkg`（layer=`districts`, driver=`GPKG`）与 CSV `district_boundaries_clean.csv`（`UTF-8-SIG`）。

输出字段：`district`（标准化区名）、`adcode`（行政区划代码）、`area_km2`（真实面积 km²）、`geometry`（gpkg 几何 / csv 的 WKT 文本）。

源要求以 `区级数据.csv` 的 WKT 为底图，并将 `区级数据.shp` 描述为“点要素”；现行统一使用 `区级数据.geojson` 的 16 个面要素（`cleaned_Data/区界.gpkg` 因几何与区名整体错配已弃用）。原要求存在两种口径，需与成员 E 确认。乡镇级数据（`乡镇级数据.csv` / `.shp`）不进入本轮 P0。
